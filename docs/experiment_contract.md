# LIMER true-16 dual-plane experiment contract

Status: **normative for new staged experiments**

Machine-readable source: `limer/configs/experiment_contract.yaml`

Contract id: `limer-true16-dual-plane-v1`

This document fixes the experiment boundary before new detector or recovery
work starts. It is a specification, not an experiment report. Numeric values
below are requirements or topology invariants; they are not measured
improvements. A run may claim compliance only when its manifest records this
contract id, the contract file hash, source revisions, topology hash, workload
hash, detector/model hash, and all runtime configuration values.

The YAML file is authoritative for automation. This document explains its
semantics. A change to a required field, metric denominator, threshold, split,
or evidence boundary requires a new contract version; it must not silently
reinterpret existing results.

## 1. Scope and non-scope

The first complete LIMER experiment targets one simulated training job on the
existing rail-optimized, dual-plane, two-stage Clos topology:

- 16 GPU ranks on four servers, four GPUs per server;
- one 16-rank AllReduce communicator, not two independent 8-rank groups;
- Plane B is the active/primary fabric and Plane A is pre-established standby;
- the primary fault scope is the 16 active Plane-B ACCESS links;
- recovery moves only QPs whose path uses the quarantined link from Plane B to
  Plane A; healthy QPs remain on Plane B;
- a whole-plane failure is a separate stress experiment and cannot be mixed
  into the per-link primary result.

The project evaluates an online architecture inside SimAI/ns-3. It does not,
by itself, establish switch-ASIC feasibility, real `ibverbs` behavior, real
NCCL timing, floating-point equivalence to a hardware collective, or a
production false-alarm rate. Those claims require separate hardware evidence.

The method is **early detection after physical onset**. The current telemetry
has no BER, FEC syndrome, optical power, temperature, lane state, or other PHY
precursor, so the result must not be described as predicting a failure before
it happens.

## 2. Frozen topology contract

The authoritative topology is generated as:

```text
gen_Topo_Template.py -topo Spectrum-X --dt --dp \
  -g 16 -gps 4 -gt A100 -bw 100Gbps -nvbw 2400Gbps \
  -asn 8 -psn 64 -apbw 400Gbps
```

Expected invariants are:

| Item | Required value |
|---|---:|
| GPU ranks / servers / GPUs per server | 16 / 4 / 4 |
| NVSwitch / ASW / PSW | 4 / 8 / 64 |
| Total nodes / regular switches | 92 / 72 |
| Physical links | 304 |
| INTRA_NODE / ACCESS / INTER_SWITCH links | 16 / 32 / 256 |
| ACCESS links per plane | 16 |
| Switch and NVSwitch physical port endpoints | 560 |
| Directional switch rows per coherent snapshot | 1120 |
| Host physical-device rows per coherent snapshot | 48 |

Plane roles are fixed for the first-stage experiment:

| Role | Host port | ASW ids | PSW ids |
|---|---:|---|---|
| Plane A, standby | 2 | 20--23 | 28--59 |
| Plane B, active | 3 | 24--27 | 60--91 |
| Same-server NVSwitch | 1 | n/a | n/a |

`link_map.csv`, not arithmetic on node ids, is the runtime authority for link
identity, endpoint ports, link class, delay, and nominal capacity. A topology
audit must additionally prove that the two switch planes are disconnected,
each GPU has exactly one ACCESS link in each plane, and all 32 ACCESS links
have their expected role.

The monitor provides coherent full-fabric snapshots no faster than 1 ms.
Each valid true-16 snapshot must contain exactly 1120 directional
switch/NVSwitch rows and 48 host-device rows, with no duplicate key. This is
not a promise to record every continuous-time queue state. Cumulative event
counters, link transitions, and interval queue high-water timestamps retain
sub-ms evidence; hard-link detection must use the event path rather than wait
for a periodic snapshot.

## 3. Fault and negative-sample taxonomy

Every event is generated by a schedule sidecar and identified by `fault_id`.
The schedule is ground truth and must never enter inference features.

### 3.1 Hard events

- `hard_disconnect`: carrier/link state becomes DOWN, normally permanent for
  the recovery experiment;
- `carrier_flap`: one or more real DOWN/UP transitions visible through the
  link-state event path.

Any injection that sets `link_state=DOWN` belongs to the Layer-0 hard-event
path, even if it lasts only microseconds. It must not be counted as evidence
that the gray classifier detects an invisible micro-flap.

### 3.2 Gray events

Gray events keep `link_state=UP` throughout their scored interval:

- `bandwidth_degradation`: remaining capacity 80%, 50%, or 20% of nominal;
  step changes and 10/50/100 ms ramps;
- `random_loss`: scheduled packet-error probabilities 0.01%, 0.1%, 0.5%, 1%,
  and 5%, subject to the simulator stability gate;
- `burst_loss`: periodic and randomized finite bursts;
- `service_degradation`: reduced effective service, growing queue/latency, and
  degraded throughput without carrier loss;
- `intermittent_service`: intermittent capacity/loss impairment while carrier
  remains UP.

If a scheduled loss interval touches no packet, it remains in scheduled-event
statistics and is marked `not_observable`; it must not be silently deleted.
Both scheduled-event recall and observable-event recall are reported. Dataset
generation should make the required scored schedules observable rather than
relying on the observable-only denominator to pass the SLO.

### 3.3 Non-fault negatives

`healthy` means no injected physical impairment. `congestion` also has no
injected physical impairment but deliberately creates high utilization,
AllReduce bursts, incast, ECMP/hash contention, queue buildup, ECN, or PFC.
Congestion labels must come from the workload/network schedule, never from a
threshold over queue, throughput, ECN, or another model input.

The primary label space is:

```text
HEALTHY
CONGESTION
GRAY_FAULT
HARD_FAULT
```

`UNKNOWN` and `INSUFFICIENT_EVIDENCE` are permitted decision states. They are
not extra ground-truth classes and cannot be converted to correct predictions
when computing recall.

## 4. Unified time model

All timestamp fields are integer ns on the same ns-3 virtual clock. Wall time
is kept separately and cannot be used in an SLO calculation. Required event
names and meanings are:

| Field | Definition |
|---|---|
| `fault_scheduled_onset_ns` | Onset requested by the immutable schedule |
| `fault_applied_ns` | Simulator time at which the injector actually changes the data path; this is `t_fault` |
| `first_observable_effect_ns` | First causal target/peer signal affected by the injection; diagnostic only |
| `layer0_observe_ns` | Carrier/link event observed by Layer 0 |
| `layer1_suspect_ns` | Lightweight gate first enters SUSPECT |
| `controller_ingest_ns` | Controller has the context needed for this decision |
| `controller_decision_ns` | Classification and confirmation finish |
| `alarm_emit_ns` | Alarm is put on AlarmBus |
| `alarm_deliver_ns` | Alarm reaches the recovery consumer |
| `alarm_actionable_ns` | Consumer can act and the alarm names link, plane, class, and action; normally consume time |
| `quarantine_applied_ns` | Target link is administratively excluded from new routes |
| `primary_quiesced_ns` | Affected primary QPs cannot issue new traffic on the target link |
| `route_update_complete_ns` | New route state is usable |
| `backup_activated_ns` | Pre-established backup binding becomes active |
| `first_backup_tx_ns` | First affected-QP data transmission on Plane A |
| `first_backup_ack_ns` | First useful acknowledgement for affected traffic on Plane A |
| `collective_abort_ns` | Old collective attempt is declared non-committable, when redo is required |
| `collective_redo_start_ns` | New attempt/epoch begins |
| `training_progress_resume_ns` | First current-epoch collective progress after cutover, supported by surviving-path traffic evidence |
| `collective_commit_ns` | Exactly one valid attempt becomes visible to the application |

`training_progress_resume_ns` is not backup activation, a route-update call,
automatic expiry of a fault, or process exit. It requires both a useful
surviving-path transport event (at minimum `first_backup_ack_ns`) and a
current-attempt collective progress event after the action.

The primary alarm time is `alarm_actionable_ns`, not an internal score-crossing
time. Offline replay with no delivery timestamp may report signal latency but
cannot pass an online detection SLO.

## 5. Metrics and denominators

### 5.1 Detection

For detector/layer `k`:

```text
detection_latency_ns = alarm_actionable_ns - fault_applied_ns
observable_detection_latency_ns = alarm_actionable_ns - first_observable_effect_ns
```

The first metric is the SLO metric. The second diagnoses limits imposed by
traffic observability. Negative latency is invalid. An event with no alarm by
the evaluation horizon is right-censored; no synthetic numeric latency is
substituted.

A true positive is the first confirmed alarm episode after fault onset that
names the target physical link and correct top-level class. Repeated samples
during the same hysteresis/cooldown episode count once. Localization to either
endpoint of the same `link_id` is equivalent. Per-class recall, precision,
F1, Top-1 localization, and latency median/P95/P99 must be reported. Quantiles
use the linear/type-7 convention and always include the sample count.

Scheduled recall uses every scheduled event in the locked test manifest.
Observable recall uses the subset with a verified data-plane effect. Neither
may be omitted.

### 5.2 False alarms

An actionable hard/gray alarm during a fault-free or congestion-only interval,
without a matching active physical fault, is a false alarm. Count alarm
episodes after hysteresis and cooldown, not every 1 ms sample.

The primary denominator is accumulated healthy plus congestion-only exposure
of the 16 active Plane-B ACCESS ports:

```text
false_alarms_per_port_hour = false_alarm_episodes /
                             (eligible_port_time_ns / 3.6e12)
```

Warm-up intervals explicitly excluded by the preprocessing contract are also
excluded from numerator and denominator. Report the exact exposure, event
count, and a 95% Poisson rate interval. The proposed detector must be compared
with immutable G1 and local-only G6 on identical runs. A reduction is called
significant only when the predeclared paired run-level bootstrap interval for
the rate difference excludes zero.

### 5.3 Recovery

Report both required intervals:

```text
post_alarm_recovery_ns = training_progress_resume_ns - alarm_actionable_ns
end_to_end_recovery_ns = training_progress_resume_ns - fault_applied_ns
training_stall_ns = last_progress_before_fault-to-first_progress_after_action interval
```

A recovery succeeds only if all of the following are true:

- the target port is quarantined and carries no new affected-QP traffic;
- every and only affected QP migrates to a healthy pre-established backup;
- at least one useful backup-path ACK is observed;
- current-epoch collective progress resumes;
- the collective correctness rule below passes.

Report affected-QP precision and recall, number of unaffected QPs moved,
replayed bytes, first backup TX/ACK, and both recovery intervals. Automatic
restoration of the same failed port is not surviving-port recovery.

### 5.4 Collective correctness

Every in-flight AllReduce must either:

1. commit exactly once with a value/fingerprint equal to the healthy oracle;
   or
2. make the old attempt non-committable, redo safely in a new epoch, and then
   commit exactly once with the oracle value/fingerprint.

All ranks must agree on attempt/epoch and result. Late old-epoch packets,
duplicate replays, partial-rank commit, and two committed epochs are failures.
The existing structural digest is useful evidence of participant/operation
identity, but it is not a tensor-value oracle and cannot alone satisfy this
gate.

## 6. Acceptance SLOs

Strict inequalities are intentional:

- all scored hard events: actionable detection `< 1,000,000 ns`;
- gray scheduled-event recall `>= 0.95` and observable-event recall `>= 0.95`;
- gray actionable detection P95 `< 100,000,000 ns`;
- every scored successful recovery: post-alarm recovery `< 1,000,000,000 ns`;
- every scored end-to-end case: fault-to-progress `< 1,000,000,000 ns`;
- affected-QP precision and recall `= 1.0`, with zero unaffected-QP moves;
- collective correctness `= 1.0` over all scored cases and zero silent wrong
  commits;
- unseen-link gray recall may fall by no more than 5 absolute percentage
  points from the seen-link result;
- the proposed detector's false-alarm rate must be significantly lower than
  the declared comparison baseline under the method in Section 5.2.

The 5-point unseen-link bound is an initial project acceptance target, not a
measured result. Changing it requires a contract version change before the
locked test set is evaluated.

## 7. Feature and label boundary

Allowed inference data are causal switch/NIC telemetry, static topology,
active/standby role, causal collective dispatch context, and state derived
only from the current or preceding samples. Utilization uses
`nominal_bandwidth_bps` from the immutable `link_map.csv`.

Forbidden inference inputs include:

- `configured_bandwidth_bps` or any dynamic capacity value changed by the
  fault injector;
- fault type, target, active flag, start/end, severity, injected rate/loss,
  recovery delay, or any other schedule field;
- labels or observability weights;
- future collective completion, final run duration, or future samples;
- split membership encoded through an identity feature.

Counter deltas must handle reset/wrap without emitting a negative rate.
Windows are causal and end at the current sample. Required windows are
5/10/20/50/100 ms, so scored runs need at least 100 ms of valid causal warm-up.

Plane A is idle standby in the primary experiment. Raw equality or an
unconditional `T_A - T_B` comparison is invalid because healthy active and
standby traffic are intrinsically asymmetric. Paired-plane features must be
role-aware and normalized to healthy active/standby baselines, or use explicit
health probes. `backupReady` proves that a binding exists, not that the backup
path is healthy.

Within one plane, the current rail-optimized topology makes the four
same-ASW ACCESS ports the same set as the four same-slot/rail GPUs. Therefore
same-ASW and same-rail are aliases, not independent ablations. The initial
contract uses:

- physical peer context, with TX at one endpoint aligned to RX at the other;
- active-plane same-ASW group;
- paired Plane-A link for the same GPU;
- cross-plane rail group formed by both corresponding ASWs.

Any future claim that independently attributes gains to same-ASW and
same-rail requires a non-collinear definition and a new contract version.

## 8. Dataset split and leakage rules

Rows are never randomly split. The atomic unit is a complete simulation run.
An immutable manifest assigns every run to exactly one of train, validation,
seen-link test, unseen-link test, or OOD/stress.

The grouping identity contains at least simulation seed/schedule, fault
instance, target physical link, workload, and topology. Unseen-link isolation
is by paired ACCESS path (`gpu_id`): if a GPU's active Plane-B ACCESS link is
held out, no fault targeting either member of that GPU's A/B pair may enter
training. At least four of the 16 GPU link-pairs are reserved as unseen target
groups. Runs containing multiple simultaneous faults, non-ACCESS faults, or
unseen fault parameters belong to OOD/stress unless explicitly predeclared as
in-distribution.

Healthy and congestion runs are also assigned by complete run. Feature
normalizers, healthy baselines, thresholds, calibration, early stopping, and
model selection use train/validation data only. Test labels are opened only
by the final evaluator after the model artifact and thresholds are locked.

## 9. Evidence classes and claim boundary

Every result row must identify one evidence class:

- `simulated_online_closed_loop`: detector and action execute on the SimAI
  virtual timeline and may qualify for simulator SLO PASS;
- `offline_causal_replay`: causal trace analysis, useful for model selection
  but not online-delivery or recovery PASS;
- `compressed_proxy`: deliberately shortened timer used only to validate
  mechanics;
- `production_policy_projection`: calculation from an external configuration
  or paper, never presented as simulator measurement;
- `real_hardware_measurement`: separately collected switch/NIC/NCCL evidence.

An online SLO requires `simulated_online_closed_loop` (for the simulator
claim) or `real_hardware_measurement` (for a hardware claim). A projection or
proxy remains `UNVERIFIED` even when its number happens to be below a limit.

Improvement values must be calculated from locked result files. Reports must
not contain hand-authored recall gains, latency reductions, or false-alarm
reductions. Current legacy artifacts are informative only:

- the true-16 hard-disconnect result is candidate evidence to be revalidated
  under this contract;
- the 288-link validation is single-plane and cannot satisfy this topology;
- the existing 300-run QG-HMM corpus is single-plane and remains only the G0
  historical baseline;
- compressed 4 ms RDMA/NCCL timers are proxies, not production error exposure.

## 10. Stage gates

Each gate produces a machine-readable PASS/FAIL report plus raw evidence. A
later phase may be developed experimentally, but no result from it is accepted
as project evidence until every preceding gate passes.

### P0 — contract and reproducibility

Deliver this document and YAML, source/submodule/config/workload/topology
hashes, a baseline manifest, and parse/schema checks. Enter P1 only when the
contract is versioned and all identifiers/thresholds are frozen.

### P1 — true-16 topology and telemetry audit

Deliver automated topology validation, per-snapshot coverage/uniqueness,
counter/queue/link-state integrity, healthy 16-rank completion, monitoring
parity, and Layer-0 hard-event timing on every active ACCESS target. The
monitoring-on/off parity workload must span at least 100 ms between its first
and last valid 1 ms snapshots (at least 101 coherent snapshots); the short
hard-fault reference run cannot satisfy this stability/warm-up requirement.
Enter P2 only with 100% topology/snapshot checks, exact monitoring parity, the
long-health span gate, and hard actionable alarms below 1 ms on all 16 active
targets.

### P2 — trustworthy corpus

Deliver immutable fault/congestion schedules, stable long workloads, all
required families/severities, all 16 active ACCESS targets, independent
congestion truth, run-level split manifests, observability accounting, and
leakage checks. Recovery runs retain at least one second of post-fault
observation. Enter P3 only when all required data-quality checks pass.

### P3 — immutable common baselines

Deliver H0, G0, frozen G1, G2, G3, host/NIC, RDMA exposure, collective
watchdog, logistic, and local XGBoost outputs in one schema on one locked
schedule. Enter P4 only when every detector is causal, reproducible, and
correctly marked as online/replay/proxy/projection.

### P4 — hierarchical topology-aware detection

Deliver Layer-1 resource accounting and gate metrics, topology registry,
local and topology-aware models, confidence/reject behavior, and non-collinear
ablations. Enter P5 only when the locked offline candidate meets gray recall,
latency, false-alarm, and unseen-link gates.

### P5 — online shadow mode

Deliver in-simulator Layer 1, model inference, event-driven upload, explicit
transport/queue/inference delays, AlarmBus events, and offline/online parity.
No recovery action is enabled. Enter P6 only when online actionable hard/gray
alarms meet their SLOs, no future data are consumed, and healthy training
still completes.

### P6 — selective recovery under oracle alarms

Deliver administrative quarantine, path-to-QP mapping, backup health check,
selective activation, route update, ACK-boundary replay, and packet epoch or
drain/fence. Use scheduled oracle alarms so detector errors cannot mask
recovery defects. Enter P7 only with 100% affected-QP precision/recall, zero
healthy-QP moves, surviving-path ACK/progress, and both recovery limits met on
all active ACCESS targets.

### P7 — collective value correctness

Deliver deterministic per-rank/chunk values or composable fingerprints,
healthy oracle comparison, epoch-aware duplicate rejection, abort/redo/commit
tests, and fault-phase coverage. Enter P8 only with exactly-once commit and
100% correct-or-safely-redone outcomes.

### P8 — true-16 closed-loop acceptance

Couple the locked detector to selective recovery and run the full
fault/congestion/seed/link matrix. Deliver unified timelines, raw and derived
data, result hashes, latency CDFs, confusion/ablation tables, false-alarm
intervals, recovery timelines, correctness results, and automatically
computed improvements. The project-level simulator claim is GO only when all
SLOs in Section 6 pass.

Real-switch/RDMA/NCCL calibration is a separate P9 gate. P8 supports only the
claim that the targets are met in the stated true-16 SimAI model.
