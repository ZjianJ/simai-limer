# 删失反馈工作置信区间与受限 UCB 探索：冻结实验方案

研究草稿。机器可复核的输入和分析边界已记录；负责人尚未完成人工科学审核。本文不是公开预注册，也不等同于统计覆盖率或真实集群可部署性认证。

## 1. 本轮要回答的问题

在既有 B8 连续 chunk 完成反馈分流之上，未完成 chunk 的等待信息能否提供额外的风险修正？在坏路径自行恢复之后，少量、有预算的探索能否避免长期沿用过时低速估计？观察目标是完整 16-rank 通信工作负载耗时，而不是给置信区间改名后默认获得速度提升。[E01,E02]

本轮待检验的设计动机如下；它们不是已经得到的结论：

- 在持续或较早发生的明显减速中，未完成信息可能早于最后一次完成反馈暴露劣化，从而减少向坏路径继续分配的新 chunk。
- 在短时严重减速、随后自动恢复的场景中，受限探索可能重新激活因旧估计而低利用的 rail。
- 在健康或轻微减速场景中，仅在区间分离时修正，可能减少过度降速；但宽区间也可能使算法完全不动作。
- 在交替 rail 劣化中，遗忘旧样本和保留未完成证据可能有用，也可能因样本滞后而进一步拖慢。

B14 相对 B13 的收益才是探索机制的增量证据。若探索次数为零，或两者完整分配轨迹相同，不能把共同收益归因于 UCB 探索。B14 相对 completed-only 消融的差异用于检查未完成信息的增量作用；差异不能单独证明名义置信区间已经校准。[E01,E02]

## 2. 已实现的估计对象

估计对象不是物理容量、端口吞吐率或 rail 聚合 goodput，而是经过启动负载归一化、截断到 `[0,1]` 的 chunk 完成速度效用。对于 chunk `i`：[E02]

```text
scale_i = 100 Gbps / ceil_pow2(launch_active_i)
X_i = min(1, bytes_i × 8e9 / (T_i_ns × scale_i))
```

`launch_active_i` 是 ASSIGN 时源端该 rail 的未完成 chunk 数，包含自身；不是首包真正上线路径时的并发数。`100 Gbps` 只是本版效用归一化常量，不能解释为在线测得的可用容量。[E02]

已完成 chunk 给出 `[X_i,X_i]`。已经真正开始 TX、当前年龄为 `a_i` 但尚未完成的 chunk 只给出：[E02]

```text
0 ≤ X_i ≤ min(1, bytes_i × 8e9 / (a_i_ns × scale_i))
```

未发首包的 chunk 不作为删失样本；同一个未完成 chunk 在不同定时器时刻仍是同一条记录；完成时替换为精确样本，不重复增加独立样本数。每个源端/rail 的集合为最高 64 个已接纳首 TX 的 assignment ID，加上更老但仍存活的 pending 记录。已完成记录在距离首 TX 超过 250 μs 后不参与当前估计，pending 不因年龄过大而消失。completed-only 消融只省略 pending 的区间贡献，不改变成员 ID 的维护规则。[E02]

对纳入的 `n` 个区间分别求均值下、上界 `mL,mU`，使用：[E02]

```text
radius = sqrt(log(2 / 0.05) / (2n))
L = max(0, mL − radius)
U = min(1, mU + radius)
```

两条 rail 各至少 8 条记录才启用风险降额；探索的乐观上界比较不要求样本成熟，允许未成熟或默认 `[0,1]` 区间，但仍须满足下节的预算等门槛。这是 Hoeffding 形状的**工作不确定性区间**；当前并发、共享队列、自适应采样、滑动成员和非平稳故障不满足经典独立同分布条件，`0.05` 不是已经验证的 95% 覆盖承诺。确定性删失上下界只约束所选记录的效用平均值，也不是下一条 chunk 的预测区间。[E02]

## 3. 分流和探索

主分流沿用 B8 的每源/目的对 byte-credit 调度器。两侧区间重叠、样本不成熟或控制关闭时，风险因子为 1。只有 `U_bad < L_good` 时才令坏 rail 因子为 `max(0.1, U_bad/L_good)`，将其乘到该 rail 最近一次 chunk 完成速度上。ACK、源端 10 μs 定时器以及每次 SELECT 决策前都更新证据。[E01,E02]

因此 B13/B14 不会直接把 `U` 当成容量给所有流量使用；也没有将最新一条 chunk 的上界误认成整条物理 rail 的容量上界。[E02]

B14 在上述主分流上增加一次可用数据 chunk 的探索，而不是发送额外负载。被考虑的是常规 credit 选择的另一 rail，须同时满足：[E01,E02]

- 此源端没有尚未完成的探索 chunk；目标 rail 没有未完成数据预留。
- 距离上次探索以及该 rail 上次 ACK 都至少 50 μs。
- 源端本地待分配 chunk 至少 8 个，避免临近尾部仍频繁探路。
- 加上本次探索后，累计探索 payload 不超过此源累计已分配 payload 的 `1/16`。
- 目标 rail 的乐观上界不低于常规目标 rail 的悲观下界。

每源最多 1 个探索 chunk 在途，不能在无 ACK 的坏 rail 上无限堆积。上述门槛也可能过于严格，导致实际实验没有探索；必须通过原始决策 CSV 报告动作次数，而不是推测“应该发生”。[E02]

输入、完整 19 个场景的故障 CSV、算法源文件摘要及动态运行库闭包在任何正式结果前冻结到 `limer/results/split_baselines/censored_ucb_20260916/protocol.json`。后续发现问题不得覆盖旧轨迹；算法修改必须另建实验根目录。本节描述的是机器协议，不构成正式第三方预注册。[E01,E03]

每场景所有策略必须读取同一字节级故障 CSV、工作负载和拓扑。同种子的 standard/B8 还要求与上一轮冻结 B8 完成时间精确一致。shadow 对 B8 不仅比较完成时间，还比较完整有序 ASSIGN 行（仅去除策略名称）。分析补充两种轨迹指标：保留全局文件顺序比较，同时按唯一 `(src,dst,sport)` chunk 键对齐比较所有 ASSIGN 字段。不同源 LP 的日志交织顺序可以改变；如果逐 chunk 时间、rail、payload 等字段完全一致，仅全局行序不同不能解释为行为改变。完成时间或逐 chunk 字段发生变化时则保留控制失配，不能默认整个差异来自决策。此处是分析指标解释的澄清，不改变冻结算法、运行协议或故障计划。[E01]

## 6. 分析与失败处理

主表显示各场景族的全工作负载完成时间。配对收益定义为 `100 × (1 − new/base)`；场景族主摘要使用“均值之比”，同时报告逐种子收益最小值、最大值和更快次数，避免与“收益的均值”混淆。三个种子不足以给出广泛泛化或显著性结论。[E01]

分析必须保留健康损失、轻微故障下无收益、某些种子的退化，以及探索零触发。除完整时长之外，检查向当时有故障端点 ACCESS 的路径分配了多少新 payload、是否有干净的另一 rail、风险因子动作次数、探索 chunk/字节，以及物理恢复后第一次重新分配的机会延迟。最后一项不是训练恢复完成时间；已分配在途 chunk 仍可能成为拖尾。[E01]

每次运行审计包括：16 rank 生命周期、payload 数量、chunk 逻辑区间、ACK/首 TX 的因果时间、适用故障 apply/revert 的准确时刻，以及删失模型与决策日志回放。证据保存为 CSV、manifest、退出码及逐运行 SHA-256。恢复执行时先复核摘要与证据摘要；证据发生变化或派生审计不一致时拒绝混用，保留旧目录。发现审计器错误时允许明确记录原因的派生结果修订，但不得改原 CSV、重跑替换失败记录或把算法失败标成通过。[E01,E04]

## 7. 灵感来源与边界

Tang、Wang、Zheng 在 AISTATS 2024 讨论奖励与反馈延迟紧耦合的随机 bandit，并提出 censored-UCB。这支持“等待本身也携带信息”的研究动机，但他们的临床存活奖励设定、分布假设及 regret 结果不是本项目并发通信效用的现成证明。[E05: [论文记录](https://proceedings.mlr.press/v238/tang24c.html)]

Zhang、Wang、Luo 在 ICML 2025 研究 contextual linear bandit 中 delay-as-payoff，使用分阶段动作淘汰等机制处理收益相关延迟。这同样只是设计启发；本版没有复现其 contextual linear 模型或算法，也不继承其理论界。[E06: [论文记录](https://proceedings.mlr.press/v267/zhang25ca.html)]

本协议的本地证据标注、负面结果保留、机审与人工批准分离使用了 Scientific Agent Skills 的 scientific-writing 流程；该工具程序参考不是本算法有效性的证据。软件参考：Kassis, T., Agarwal, V., He, Y., Patel, D., & Brueckner, A. M. (2026), *Scientific Agent Skills: A Library of Procedural Knowledge for Research Agents*, arXiv:2609.00065，2026-09-16 核验当前记录为 v2。[E07: [软件论文记录](https://arxiv.org/abs/2609.00065)]
